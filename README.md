# Тренировки — PWA

Дневник тренировок: тренировка → упражнения → подходы (вес, повторы, минуты), календарь со статистикой
в стиле `../workouts.html` (серия недель, тренировки за месяц, типы), журнал, графики, экспорт и импорт JSON/CSV.
Работает в браузере и как приложение на экране «Домой» iPhone. Сервера и аккаунта нет: данные живут на устройстве.

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173 — разработка, без service worker
npm test             # юнит-тесты (форматы JSON/CSV, статистика, хранилище)
npm run build        # проверка типов + сборка в dist/
npm run preview      # http://localhost:4173 — собранная версия, с service worker и офлайном
npm run test:e2e     # e2e: десктопный Chrome и Chrome с экраном/тачем iPhone (нужен установленный Chrome)
```

`npm run test:e2e:webkit` гоняет то же в WebKit (движок Safari), но Playwright 1.65 WebKit падает при запуске на macOS 26.0 —
на этой машине iOS проверялся вручную в симуляторе Xcode (Safari, iOS 26).

Иконки (`public/*.png`, `favicon.ico`) сгенерированы из `public/icon.svg`: после правки SVG — `npm run icons`.

## Устройство

| Путь | Что там |
|---|---|
| `src/model/` | типы (`Workout → Exercise → WorkoutSet`), производные величины (объём, минуты, сводки) |
| `src/io/json.ts`, `src/io/csv.ts` | форматы файлов: запись, чтение, проверка с понятными ошибками |
| `src/io/files.ts` | выдача файла пользователю (меню «Поделиться» на телефоне, скачивание на компьютере), выбор формата при загрузке |
| `src/store/` | хранилище: весь дневник — один JSON-документ в `localStorage`, пишется синхронно при каждом изменении; отмена удаления и импорта; напоминание о бэкапе |
| `src/stats/` | серия недель, недельные суммы, прогресс упражнения, шкалы графиков |
| `src/ui/` | экраны (Preact + signals), графики — самописный SVG без библиотек |

Зависимости в рантайме — только `preact` и `@preact/signals` (≈26 КБ gzip вместе с приложением).

## Форматы файлов

**JSON** — полная копия, из неё всё восстанавливается один в один:

```json
{ "format": "sport-log", "version": 1, "exportedAt": "2026-11-23T10:00:00.000Z",
  "workouts": [ { "id": "…", "date": "2026-11-23", "title": "Грудь", "type": "strength", "minutes": 50,
                  "exercises": [ { "id": "…", "name": "Жим лёжа",
                                   "sets": [ { "id": "…", "weight": 62.5, "reps": 10, "minutes": null } ] } ] } ] }
```

`type`: `strength`, `cardio`, `hiit`, `mobility`, `stretching`, `yoga`, `other`. `minutes` тренировки `null` — считать по подходам.

**CSV** — для Excel/Numbers: разделитель `;`, десятичная запятая, UTF-8 с BOM, строка на каждый подход:

```
Дата;Тренировка;Тип;Длительность, мин;Упражнение;Подход;Вес, кг;Повторы;Время, мин;ID тренировки
```

Загружается обратно: колонки ищутся по заголовку (порядок не важен, лишние игнорируются, понимает и английские
`date;workout;type;workout_minutes;exercise;set;weight_kg;reps;set_minutes;workout_id`), даты `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`
(так их пересохраняет Excel), тип — ключом или названием («Йога»). Строки без ID группируются в тренировку по дате и названию.

Загрузка файла: «Заменить» (всё текущее → файл) или «Объединить» (новые добавляются, совпадающие по ID заменяются).
Импорт можно отменить: данные до него сохраняются.

## Сохранность данных — важно для iPhone

- Ставить на экран «Домой» (Safari → «Поделиться» → «На экран „Домой“»). В обычной вкладке Safari по правилам WebKit
  стирает данные сайта, который не открывали 7 дней использования браузера; на приложения с экрана «Домой» это правило
  по документации WebKit не распространяется. Приложение само подсказывает это на iPhone.
- **Удаление иконки с экрана «Домой» удаляет данные.**
- Данные привязаны к адресу сайта. Если адрес (домен или путь) сменится — на новом адресе будет пусто: перенос только
  через экспорт → импорт. Поэтому адрес публикации выбирается один раз и навсегда.
- Резервная копия: «Данные» → «Сохранить JSON» → «Сохранить в Файлы» (iCloud Drive). Приложение напоминает, если копии
  нет или она старше 14 дней при новых изменениях.
- Телефон и компьютер — разные хранилища; синхронизации нет, перенос файлом.

## Публикация

Адрес: **https://vladimirobolonnyy.github.io/sports_log/** — не менять (данные привязаны к адресу).

Каждый push в `main` запускает `.github/workflows/deploy.yml`: юнит-тесты → сборка → выкладка `dist/` на GitHub Pages
(однократно: Settings → Pages → Source: «GitHub Actions»). После выкладки установленное приложение покажет
«Вышла новая версия → Обновить»; данные при обновлении не трогаются.

`dist/` собирается с относительными путями, поэтому работает из любой папки любого HTTPS-хостинга
(service worker и «Поделиться» работают только по HTTPS).

Установка на iPhone: открыть адрес в Safari → «Поделиться» (в iOS 26 — в меню «⋯») → «На экран „Домой“» →
дальше открывать только с иконки.
